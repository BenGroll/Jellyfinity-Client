# Scout: v0.7.0 - Bulk music selection and playlist actions

Generated by scouting the repository ahead of implementation. This is a
starting brief, not a replacement for `Roadmap to v0.7.md` or `AGENTS.md` —
an implementing agent should still run
`python3 tools/agent_context.py v0.7.0` first.

## Goal

Let a user select more than one song where they already browse music, and
add the selection to an existing or new playlist in displayed order.

## Current state (confirmed by inspection)

- **No selection model exists yet.** A repo-wide search for
  `isEditing`/`editMode`/`selectionMode`-style state found nothing; this is
  genuinely new application state, not an extension of an existing mode.
- The song-list building block used across every required surface is
  `TrackRow` in `lib/features/music/presentation/widgets/music_rows.dart`
  (~line 108). It already takes optional per-row callbacks
  (`onTap`, `onPlayNext`, `onAddToQueue`, `onRemoveFromPlaylist`,
  `onMoveUp`/`onMoveDown`, `dragHandle`, `downloadAction`) and is the right
  extension point for a `selected`/`onSelectToggle`-style addition, matching
  its existing "optional callback, `null` means the screen doesn't offer it"
  convention.
- Confirmed `TrackRow` callers — these are the required multi-select
  surfaces:
  - `lib/features/music/presentation/search/SearchCategoryPage.dart`
    (search results)
  - `lib/features/music/presentation/detail/AlbumDetailPage.dart`
    (album tracks)
  - `lib/features/music/presentation/detail/PlaylistDetailPage.dart`
    (playlist rows)
  - `lib/features/favorites/presentation/FavoritesPage.dart` (Favorites)
  - `lib/features/downloads/presentation/DownloadsPage.dart` (Downloads)
  - `lib/features/music/presentation/library/LibraryPage.dart`
  - `lib/features/music/presentation/search/InlineMusicSearch.dart`
  - Artist songs render through `SongsCubit`/`ArtistDetailPage.dart`, which
    does not appear in the `TrackRow(` grep — confirm at implementation time
    whether it already delegates to `TrackRow` deeper in the widget tree or
    needs its own wiring.
- **The add-to-playlist mechanism already exists and is reusable as-is:**
  `MediaPlaybackActionsRow._addToPlaylist` (`lib/features/music/
  presentation/widgets/MediaPlaybackActionsRow.dart`, ~line 156) already
  calls `showPlaylistPicker(context)` (`PlaylistPickerSheet.dart`) for
  either an existing or a newly-created playlist, then
  `PlaylistRepository.addTracks(playlistId, trackIds)`. Bulk selection can
  drive the same picker and the same `addTracks` call with the selected
  `MediaId`s in display order — no new domain contract needed for the
  "happy path".
- `PlaylistRepository.addTracks` (`lib/domain/media/PlaylistRepository.dart`,
  line 43) returns a single `Result<void>` for the whole batch — **not**
  per-track results. The spec's "explicit handling for duplicates,
  unavailable rows, partial success" is therefore new work: either extend
  the contract to report per-item outcomes, or decide client-side
  pre-filtering (dedupe by `MediaId` before calling, treat any failure as
  all-or-nothing) is sufficient and document that choice. Worth an explicit
  decision recorded in an ADR given `PlaylistRepository` is a shared
  contract (`lib/infrastructure/media/CachedPlaylistRepository.dart` and
  `lib/infrastructure/jellyfin/media/JellyfinPlaylistRepository.dart` both
  implement it).
- `MediaId` (`lib/domain/media/MediaId.dart`) is the existing stable media
  identity type — use it as the selection key, per CONTEXT.md's
  architecture invariants (no raw Jellyfin DTOs in presentation/state).

## Suggested shape (not prescriptive)

- A selection cubit/model scoped per active page + profile + server (mirror
  how `SettingsCubit`/`PlaybackCubit` are already profile/server-aware, if
  such a pattern exists in `app/di` — check `service_locator.dart` for
  scoping precedent before inventing a new one).
- Entry to selection mode from within each of the confirmed `TrackRow`
  surfaces above; keep it page-local (spec: "never load a whole result set
  merely because selection mode started" — bounded/paged pages must keep
  behaving that way while a selection spans multiple loaded pages).
- Bulk action reuses `showPlaylistPicker` + `PlaylistRepository.addTracks`,
  passing selected `MediaId`s in displayed order.
- Explicit UI/state handling for: duplicates already in the target
  playlist, rows that became unavailable between selection and add, partial
  success, cancel, in-selection navigation, and account/profile switch
  clearing the selection.

## Non-goals (per spec's v0.7.x arc)

Collaborative playlists, cross-user editing, cross-server playlist identity,
external recommendation services, automatic download synchronization, video
playlists, a general automation language — and, specific to v0.7.0, nothing
from v0.7.1-v0.7.4 (artwork, smart playlists, hardening) is in scope.
