# Scout: v0.6.1 - Settings as places

Generated by scouting the repository ahead of implementation. This is a
starting brief, not a replacement for `Roadmap to v0.6.1.md` or
`AGENTS.md` — an implementing agent should still run
`python3 tools/agent_context.py v0.6.1` first.

## Repo-state caveat

`ROADMAP.md` currently has **duplicate, conflicting rows** for v0.6.0 and
v0.6.1 (lines 56-59). One v0.6.1 row links to `Roadmap to v0.7.md#v061...`,
which does not contain a v0.6.1 section — `agent_context.py v0.6.1` fails

`Roadmap to v0.6.1.md#v061...`. This should be cleaned up (drop the stale

unambiguously.

## Goal

Replace the single scrolling `SettingsPage` with named category places, each
with its own route, reachable from a settings home. Re-homing only — no
option's behavior changes.

## Current state (confirmed by inspection)

- `lib/features/settings/presentation/SettingsPage.dart` (488 lines) is one
  `ListView` with inline section headers (`Padding` + `Text` at
  `t.typography.titleMedium`) for: Navigation style, Streaming quality,
  Downloads (+ Wi-Fi-only), Offline library, Crossfade, Volume normalization.
  These map directly to the spec's "playback and sound", "downloads and
  storage", and "library and offline" categories.
- **No existing UI surface** for the "connected-playback and devices"
  category. v0.6.0's default playback destination, controllable-by-others,
  and group playback behavior live only in
  `lib/app/connected_playback/PlaybackControlCubit.dart` (and
  `lib/domain/connected_playback/SyncPlayTransport.dart`) with no settings
  screen wiring yet — this category is new UI, not a move.
- `lib/app/settings/SettingsCubit.dart` is the single source of truth for
  every persisted preference: one `SettingsState` (Equatable), one
  `KeyValueStore`-backed key per field, `loadInitial*` static methods read in
  `bootstrap()`, and setters that no-op when the value is unchanged. This
  cubit is shared by `PlaybackCubit`/`DownloadsCubit` — splitting the *UI*
  into categories should not require splitting this cubit unless the
  connected-playback options need their own persisted keys added here.
- Routing: `lib/app/router/route_paths.dart` declares
  `RoutePaths.settings = '/settings'` / `RouteNames.settings = 'settings'`
  as flat string constants; `lib/app/router/AppRouter.dart` registers one
  `GoRoute` per path. Category routes should follow the same
  `RoutePaths`/`RouteNames` const-pair convention, nested under `/settings`.
- Windowed/compact breakpoint precedent: `MediaQuery.sizeOf(context).width <
  600` (see `lib/features/playback/presentation/DevicePickerSheet.dart`) is
  the existing convention for "show list+detail together vs. one at a time".
  Reuse this threshold rather than inventing a new one.
- Television focus/D-pad order: `lib/features/shell/presentation/
  TelevisionNavigationRail.dart` and ADR-0036
  (`docs/adr/ADR-0036-fire-tv-platform-support.md`) are the named precedent
  the spec points at for explicit initial focus.

## Suggested shape (not prescriptive)

- A settings-home widget listing categories (playback and sound; downloads
  and storage; connected playback and devices; library and offline; account
  and server; about/diagnostics), each a `GoRoute` child under `/settings`.
- Move existing sections into their category screens verbatim — same
  `SettingsCubit` calls, same copy, same widgets (`_SettingsOption`,
  `_StreamQualityDropdown`, `_DownloadQualityDropdown`,
  `_CrossfadeDurationSlider` can likely move as-is or be lifted to shared
  widgets if more than one category needs them).
- New: a connected-playback category screen reading/writing the v0.6.0
  options currently only exposed via `PlaybackControlCubit` — decide during
  implementation whether these need new `SettingsCubit` keys or should read
  `PlaybackControlCubit` directly.
- Windowed layouts: category list + selected category shown together above
  the 600px breakpoint; phone/TV show one at a time, TV with an explicit
  initial focus per ADR-0036.
